1. How the site works, in one page

The site is a static site. There's no database and no admin panel on the server. Instead, a program called Eleventy reads the content from a handful of data files, pours it into page templates, and writes out finished HTML pages. Those finished pages are what visitors get.

  1. Content lives in data files in src/_data/: articles.json, team.json, services.json, prices.json, locations.json, faq.json, reviews.json and a few smaller ones.
  2. Templates decide how it looks: the files in src/ ending in .njk and the styles in src/css/. One template, for example, makes a page for every specialist in team.json.
  3. The build (npm run build) turns data and templates into the finished site in the _site/ folder: about 150 pages plus the sitemap, the search index and the redirect list.
  4. Netlify hosts the site. Every push to the main branch on GitHub makes Netlify run the build and publish the result, usually within a minute or two.

Two consequences worth remembering:

  • Changing content means editing a data file and pushing it. The pages update themselves at the next build.
  • Most things switch on and off with a "published" field. Articles, specialists and services each have one. Set it to false and the page disappears from the site, menus, sitemap and search at the next build. The data stays in the file, so it can be switched back on.

4. Site search

  • A Szukaj page (/szukaj/) searches the whole site: articles, services, specialists, locations and FAQ. Results can be narrowed to one section.
  • It's reachable from the menu, from the magnifier icon in the top bar (on computers), from the mobile bottom bar (where it replaced "Przyjedź"), and from a search box at the top of the Artykuły page, which searches articles only.
  • It uses Pagefind, the same tool as on stacherski.online. At every build Pagefind reads the finished pages and writes a small search index next to them. The search then runs entirely in the visitor's browser, with no server.
  • The search page itself is hidden from Google (noindex), so result pages never show up as thin duplicate pages. Search doesn't affect Google rankings either way; it's there for visitors.

5. Redirects: old addresses that keep working

Why they matter

Google, other websites and people's bookmarks still know addresses from the old site and from pages that have since moved. Without redirects those lead to "page not found". The ranking and links that old page earned are lost, and the visitor leaves. A redirect tells the browser and Google "this moved permanently, go here instead" (HTTP status 301). Google then passes the old page's standing to the new one.

How a static site can redirect at all

A static page can't redirect itself; the hosting server does it before any page is involved:

  1. The build writes a plain text file, _redirects, next to the pages. Each line is a rule: old-address new-address 301.
  2. When Netlify publishes the site, it reads that file into its servers.
  3. When someone asks for an address, Netlify checks the rules first. On a match it doesn't send a page; it answers "moved permanently" with the new address, and the browser goes there automatically.

Two rules decide which redirect applies:

  • An existing page always wins. If a real page exists at the address, Netlify shows it and ignores the rules, so the broad "catch-all" rules can't hide a live page.
  • The first matching rule wins, so specific rules come first and general ones last. A * at the end of a rule means "anything below this", e.g. every old title variant of article 147.

How our redirect list is built

Nobody edits _redirects by hand. The template src/_redirects.njk generates it at every build, in this order:

OrderRulesComes from
1Hand-picked moves: renamed services, old CMS addresses, the QEEG PDF downloads, the Anoreksja address typosrc/_data/redirects.json
2Specialists who left: their page → a chosen page, or the team pageteam.json ("published": "No" plus optional "redirectTo")
3Team addresses written without Polish letters (/zespol/…) → the right specialistgenerated from team.json
4Any old address of an article (old titles, the old /baza-wiedzy/ section) → its current page, or for an unpublished article → the closest own article or servicearticles.json + articleRedirects.json
5Catch-alls: anything else that no longer exists in a section → that section's main pagefixed in the template

What Search Console showed, and what was done about it

Google Search Console listed 149 addresses returning "not found". Nearly all of them follow a few patterns: old article titles, the old /baza-wiedzy/ addresses, /zespol/ without Polish letters, former specialists, and a handful of old pages. Each now redirects to the best current page. Tested with a script that imitates Netlify, 141 of the 145 distinct addresses lead to a live page in one step. The four that stay as "not found" really are junk (/do-skasowania…, /showpicture.aspx), and they now get a proper "page not found" page with a search box.

Other items from that clean-up:

  • The site's own links now end with a slash (/kontakt/, not /kontakt), which removes an unnecessary redirect step. That was the cause of the 122 "page with redirect" entries.
  • The two QEEG leaflets ("Co to jest badanie QEEG", "Przygotowanie do badania QEEG") are back on the site as PDFs and linked from the QEEG page. Their old download addresses lead straight to them.
  • Seven services no longer offered (e.g. Leczenie alkoholizmu, Tutoring rodzinny) no longer have pages; their addresses go to the closest current service.

Keep in mind: redirects only work on Netlify. The local preview (npm start) ignores them. If the site ever moves to another host, the same rules have to be written in that host's format, but the data files stay the same.

6. Google reviews on the site

Where the reviews came from

The reviews were read from the four Google Business profiles (Centrum Psyche, Diagnoza ADHD Wrocław, PSYCHE Kids, QEEG Wrocław), using Chrome with your Google account, reading only. The 11 that were new went into src/_data/reviews.json, next to the 21 already there. Each review is tagged with the specialist (only when the text names them) and the service.

Where they appear

  • Specialist page: reviews that name that specialist.
  • Service page: every review about that service.
  • Opinie page (new, /opinie/, in the menu under O nas): all reviews, newest first, each linked to its specialist and service.
  • Homepage: a summary, "4,8 ★★★★★ · Średnia ocena z 32 opinii pacjentów w Google", linking to the Opinie page.

Rules chosen along the way

  • Only 4 and 5 star reviews are shown. The two 1-star reviews stay in the file and still count in the average. Deleting them would make the summary read 5,0 while it claims to be based on Google reviews, which would be misleading.
  • Reviewers appear as first name and initial ("Karina H."), because these are visits to a mental-health clinic.
  • Reviews with stars but no text count in the average but don't get a card.
  • Star ratings won't appear in Google's results for these reviews. Google doesn't show them for reviews a business publishes about itself.

Repeating it later

The whole procedure is saved as a project skill for Claude Code, in .claude/skills/update-google-reviews/. Asking Claude to "update the Google reviews" in this project (or typing /update-google-reviews) follows the same steps, with helper scripts that read the review pages, skip reviews already in the file and convert Google's dates.

7. The SEO pass

Changes aimed at ranking higher in Google, roughly in order of how much they're likely to matter:

Only your own articles are published

Of 259 published articles, 179 weren't written by Centrum PSYCHE; they had been republished from other websites. Google judges a site's quality as a whole, and a large share of copied health content can hold back the clinic's own pages. All 174 remaining borrowed articles, plus 5 duplicate articles, are now unpublished. They're still in articles.json, waiting for your decision. Each old address redirects to the closest own article, or to a service page where no own article covers the topic, e.g. news or celebrity stories. The choices are in src/_data/articleRedirects.json. The site now has 80 articles.

Every article links to services

  • Every article ends with a "Jak możemy pomóc" block: one to three service cards chosen for its topic. The choices are in src/_data/articleServices.json.
  • 115 articles also got one link inside the text, on a natural phrase such as "DIVA-5", "ADOS-2" or "terapia dla par".
  • Links like these help Google understand which service pages matter, and help readers find the next step.

What Google shows in results

  • Descriptions: the snippet under each result used to contain visible HTML code (<p>) on every article and ran far too long. It's now plain text of about 155 characters, cut at the end of a sentence.
  • Titles: the homepage title is now "Psycholog i psychoterapeuta Wrocław – Centrum PSYCHE" instead of 109 characters. The brand appears only once per title, the list pages are numbered ("Artykuły – strona 2"), and no two pages share a title.
  • Image descriptions: images no longer describe themselves with file names like pexels-mikhail-nilov-8654221.jpg.

Speed

  • Each page used to load 17 separate style files; now it loads one (/css/site.css, combined at build time from the same files).
  • The fonts are served from the site itself, and the two used above the fold load first. The menu script no longer delays the first paint.
  • The site looks exactly the same; it just draws sooner, which counts for Google, especially on phones.

Smaller fixes

  • The duplicate articles (e.g. two "Co to jest depresja?") were merged, and the Anoreksja article's address typo (aoreksja) was corrected, with a redirect from the old address.
  • Text panels on service pages and the article cards no longer grow when the mouse moves over them, so text stays still while it's being read.
  • An old link between the two parts of "Dlaczego mi nie wychodzi?" was repaired, and an article linking to a service page that no longer exists now points to the online consultations page.

8. Cookie banner and consent

Why it was needed

Google Tag Manager on the site runs Google Analytics (two properties) and Google Ads conversion tracking. Until now they started as soon as a page opened and set cookies without asking, which isn't allowed in the EU for analytics and advertising cookies. Since March 2024 Google also expects Consent Mode v2 in the EEA for Ads measurement to keep working properly.

How it works now

  1. Before anything from Google loads, a small script in the page head tells Google "no consent yet". Google's tags then run without cookies. If the visitor already chose on an earlier visit, that choice applies straight away.
  2. The banner asks once, in Polish, with "Akceptuję wszystkie", "Odrzuć" (deliberately as prominent as accepting) and "Ustawienia". The settings split cookies into necessary (always on), analytics (Google Analytics) and marketing (Google Ads and Google Maps).
  3. On accepting, Google is told consent was given, and only then are its cookies set (_ga, _gcl_au and the like). On withdrawing, Google is told again and those cookies are deleted.
  4. Changing your mind: "Ustawienia cookies" in the footer reopens the settings at any time. The choice is remembered for six months in a cookie called cc_cookie.

The banner is CookieConsent (v3, free and open source), installed as an npm package and served from the site's own domain, with no outside service and no fee. Its texts and categories are in src/script/consent.js; its colours are in src/css/consent.css.

Related changes

  • The map on Kontakt loads only when someone clicks "Pokaż mapę", or once they've accepted marketing cookies, because Google Maps sets its own cookies. Until then a box shows both addresses and an "Otwórz w Mapach Google" link.
  • Fonts are self-hosted: the files come from src/fonts/ instead of Google Fonts, so a visit no longer sends anything to Google just to draw text. It's also slightly faster.
  • Privacy page: /polityka-prywatnosci/ exists as a placeholder. It lists the cookies and explains how to change consent, says the full policy is in preparation, and is hidden from Google (noindex) until the real text is in.
  • The hidden Tag Manager fallback for visitors without JavaScript was removed, since it would have tracked them without any way to ask.

Expect in Google Analytics and Ads: reported visits and conversions will drop somewhat, because visitors who refuse aren't counted with cookies. Google estimates part of the gap with its modelling. That's the expected effect of asking, not an error.

9. How to do common jobs

Publish a new article
Add an entry to src/_data/articles.json with the next free id (never reuse a number), "published": true, "ownArticle": "Yes" and today's date. Add a line to src/_data/articleServices.json with the services it should link to.
Take an article off the site
Set "published": false. Its address then goes to the article list, unless you add a better target to articleRedirects.json.
A specialist leaves
In team.json, set their "published" to "No" and keep the entry. They vanish from all lists and their page redirects to the team page. To send it somewhere more useful, add e.g. "redirectTo": "/oferta/qeeg-wroclaw/".
A service is no longer offered
In services.json, set "published": false, then add a line to redirects.json pointing its address to the closest service. Without it, the address goes to the Oferta page.
Any other page moved
Add { "from": "/old-address/", "to": "/new-address/" } to src/_data/redirects.json.
Update the Google reviews
Ask Claude Code in this project to "update the Google reviews". Chrome with the Claude extension needs to be connected.
Show or hide low ratings
Change REVIEWS_MIN_STARS in eleventy.config.js: 1 shows every review, 4 is the current setting.
Change the cookie banner
Texts, categories and the cookie list are in src/script/consent.js. If a new tracking tool is added in Tag Manager, add it to the right category there and on the privacy page. When the privacy policy link changes, update POLICY_URL at the top of that file.
Check changes before they go live
Run npm start and open http://localhost:8080. Everything works there except the redirects.

10. Open decisions and next steps

Two Business Profiles carry keyword names. "Diagnoza ADHD Wrocław" and "QEEG Wrocław" are separate Google Business Profiles at the Białowieska address. Google's rules say a profile's name must be the real business name, and profiles like these risk suspension, which can affect the main profile too. It's worth deciding whether to merge them into Centrum Psyche or rename them within Google's rules.

  • Privacy policy text: /polityka-prywatnosci/ is only a placeholder. The full policy (who processes data, for what, legal bases, rights, retention) needs writing and a legal check, especially for a clinic handling health data. When it's ready, remove noindex from the page.
  • Tag Manager consent settings: open each tag in Tag Manager and check that the Google Analytics and Google Ads tags use their built-in consent checks (the default for Google's own tags). Any non-Google tag added later needs a consent condition.
  • The borrowed articles: they're unpublished, not deleted. Decide whether to delete them for good, rewrite some as your own, or leave them as they are.
  • Topics you don't cover yet: schizophrenia, psychosis, bipolar disorder and OCD have no own article; their old addresses currently go to a service page. These topics draw searches and would make good new articles.
  • A few weaker redirect matches are worth checking in articleRedirects.json: OCD articles → "Zaburzenia lękowe", PTSD → the childhood trauma article, erectile dysfunction → "Seksualność człowieka".
  • Authors on articles: for health content Google looks for who wrote and checked it. Adding the specialist, their qualifications and a "zweryfikowane przez … / aktualizacja" line to each article would help.
  • More Google reviews: 23 reviews on the main profile is low for a clinic this size. A short request after a visit (the review link as a QR code at reception, or in the follow-up text message) usually makes the biggest difference.
  • Search Console: after each deploy with redirect changes, click "Sprawdź poprawkę" (validate fix) on the "not found" report so Google re-checks sooner. Expect the number of indexed pages to drop for a few weeks as Google replaces the borrowed articles with the pages they redirect to. That's intended.
